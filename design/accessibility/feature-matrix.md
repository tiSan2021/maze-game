## 0. 阅读说明

- **开关标记**：● 开启　◐ 部分 / 降级　○ 关闭　— 不适用
- **性质列**：`硬约束` = 设计或玩法冻结项，**三级均不可关**；`可访问性` = 真正随档位开关的项
- **降级策略**：指该特性在关闭或减弱时，**如何保证信息不丢失**。凡"关闭即丢信息"的特性不得做成开关（见 §5）

## 3. 动效（A5）

### 3.1 A5 的准确口径（**重要澄清**）

> **A5 原文判据为「移动插值 ≤200ms」，约束对象是移动插值，不是全部动效。**

本项目值：**格移动 120ms（smoothstep）✓ 达标**。

据此把动效分三类，仅前两类受 A5 约束：

| 类别 | 项目 | 时长 | 受 A5 约束 |
|---|---|---|---|
| **① 移动插值** | 格移动 | **120ms** | ✓（上限 200ms） |
| **② 交互反馈** | 撞墙 80ms · 拾取 200ms | ≤200ms | ✓（且本来就在限内） |
| **③ 过场 / 结算** | 开门 280ms · 失败 320ms · 过关 400ms · 关卡切换 250+250ms | >200ms | ✗ **不受 A5 约束** |

**③ 类不受约束的前提（必须同时满足，写入实现）**：
1. **不阻塞输入**：过场播放期间玩家可继续操作或可立即跳过（阻塞 ≤200ms）。
2. **受 `motionScale` 控制**（见 M2），可整体关闭。
3. 不承载"必须被看见才知道"的信息 —— 唯一例外是**状态联动**（门由网格变实心），该项在 `motionScale=0` 时必须以瞬时切换保留（见 M3）。

> **给 engineering-lead 的提醒**：不要把 A5 误读为"所有动效 ≤200ms"而砍掉过场。过长场是节奏与反馈需要；真正要守住的是**操作响应**不被拖慢。

## 5. 关于"哪些特性不得做成开关"

**原则：凡关闭后会导致信息丢失的特性，一律不提供关闭选项。** 依据 `levels.md` §3（图案填充是识别基础，非装饰）。

| 不得关闭 | 原因 |
|---|---|
| V2 图案填充 | 去色后可辨识性的唯一载体 |
| V3 钥匙双编码、V5/V6 对比度 | GDD③ K3 强制 + WCAG 底线 |
| M3 状态联动（门网格→实心） | 承载"钥匙-门"因果信息，是本项目信息价值最高的单次反馈 |
| F2 铅笔笔迹 | `walked` 状态的唯一视觉表达 |
| F3 墙邻感知 | 零成本，关闭只带来挫败 |
