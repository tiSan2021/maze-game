## 0. 一句话结论

**本项目可用档位为 Standard（推荐）或 Comprehensive（可选升级）；Basic 明确不可用。**

理由：本项目的第二编码通道是**图案填充（hatching）**，它是识别逻辑的组成部分而非附加的可访问性功能。关掉它等于关掉六类元素的可辨识性基础，Basic 档因此**在结构上不成立**。详见 §3。

## 1. 三级定义

### Basic — 最小合规

| 项 | 内容 |
|---|---|
| **定位** | 满足"不做就无法运行"的最小集；不做任何主动的可访问性设计 |
| **面向玩家** | 无特殊需求的普通玩家 |
| **覆盖能力** | 键盘可操作、文字可读、界面可点击。**不含**任何色觉 / 动效 / 认知适配 |
| **本项目状态** | **❌ 不可用** —— 见 §3 |

### Standard — 推荐档（**本项目默认**）

| 项 | 内容 |
|---|---|
| **定位** | 以**低成本改造**覆盖主流可访问性需求；所有核心信息具备**不依赖单一感官通道**的冗余编码 |
| **面向玩家** | 色觉障碍（约 8% 男性）、轻度低视力、动效敏感、需键盘操作、有轻度认知负荷顾虑的玩家 |
| **覆盖能力** | 形状 + 图案双重编码 · 对比度达标 · 减少动效开关 · 字号三档 · 键盘可达 + 可见焦点环 · 迷雾减淡 / 关闭迷雾 · 四态图例 · 无闪烁（<3Hz） |
| **成本** | **约 2.2 人天**（明细见 `feature-matrix.md` §4） |
| **判据** | 全部 §5 准入条件满足 |

### Comprehensive — 完整适配

| 项 | 内容 |
|---|---|
| **定位** | 在 Standard 基础上提供**可切换的替代呈现方案**，覆盖重度与特定类型障碍 |
| **面向玩家** | 重度低视力、完全色盲、认知 / 记忆障碍、需 assistive tech 的玩家 |
| **覆盖能力** | Standard 全部 + 三型色盲色表切换 + 高对比模式 + 图案密度可调 + 逐项动效开关 + 无级字号。**注**：「增强记忆」经裁决**不纳入 MVP**（列为候选增强）；「视觉替代音效」**作废**（用户裁决 MVP 不含音频） |
| **成本** | **约 4.5–6 人天**（在 Standard 之上增量约 2.5–4 人天；较初版下调，因移除上述两项） |
| **判据** | Standard 全部条件 + 三型色盲色表经实测验证 |

## 3. 为什么 Basic 在本项目不可用（关键论证）

**结论：Basic 关掉的不是"便利功能"，而是识别能力本身。**

1. **图案填充是第二编码通道，不是装饰。** `art-bible.md` v2 §2② 已量化证明：亮底（纸底 `#F4F1EA`）下，满足"对底 ≥3:1"的元素亮度被压缩至 `L ≤ 0.26`，对应 L* 可用区间仅 **42.6**（15.5→58.1）；六类元素 + 三档钥匙色共 8 个信号，平均 L* 间隔仅 **6.09**，远低于小尺寸可靠区分所需的 **≥10**。即便最优分配，配对 2 紫（L* 29.9）与出口（L* 30.3）仍只差 **0.4**。
2. **因此"去色后可辨识"完全依赖图案填充。** 关闭图案 = 色觉障碍玩家与低视力玩家**无法区分钥匙与出口、玩家与赭石钥匙**。
3. **图案的实现成本已内含于墙体绘制**，不做成开关反而更简单。把它列为"可关闭项"是纯负收益。

> **推论**：本项目的可访问性档位选择实际是 **Standard vs Comprehensive** 的二选一，不是三选一。任何"先做 Basic 以后再说"的排期都会产出不可交付的版本。

## 4. 档位选择指引

| 若满足以下条件 | 选 |
|---|---|
| 单局 1–3 分钟的休闲小游戏；lean 强度；工期紧；无明确重度无障碍需求 | **Standard（推荐）** |
| 产品定位含"无障碍标杆"；有低视力 / 色盲用户群体反馈；工期允许 +3–5 人天 | **Comprehensive** |
| 任何情况 | ~~Basic~~（结构上不可用） |

**给主理人的建议**：选 **Standard**，并把 Comprehensive 的色盲色表与高对比常量**预先按常量表结构落位**（成本近乎为零，见 §5）。这样未来升级只需替换色表，不触碰绘制逻辑。

## 5. 升级路径与常量表依赖（与 engineering-lead 架构的共同前提）

**核心约束：档位升级 = 换常量 + 开开关，不改绘制逻辑。**

| 从 Standard 升到 Comprehensive 时 | 实现方式 | 涉及文件 |
|---|---|---|
| 三型色盲色表切换 | **替换色表常量**（红 / 绿 / 蓝三型各一张完整色表） | `palette.ts` |
| 高对比模式 | **替换一组常量**（全部识别线提至 ≥7:1） | `palette.ts` |
| 图案密度可调 | **调参**（间距 5px→3px，线宽 2px→2.5px） | `pattern.ts` |
| 逐项动效开关 | **开关 + 时长乘数** | `motion.ts` |
| 无级字号 | **CSS 变量 + 布局度量** | `metrics.ts` |
| 迷雾减淡 | **替换记忆态色组常量**（2.14:1 → ≥3:1） | `palette.ts` |
| **关闭迷雾**（✅ 已采纳进 MVP） | **⚠ 唯一需要代码分支的项** —— 覆盖 `cellRenderState` 返回值（`UNKNOWN`/`MEMORY_WALKED` → 对应 `VIEW_*`），**不改变 `visible`/`visited` 集合**。0.1 人天，复用关 1–8 全烘焙路径 | 渲染层（GDD① §4.7 已授权） |
| ~~增强记忆（看见即记住）~~ | **不纳入 MVP**（AX-1 裁决）。若将来重启，需改 `visited` 语义，触及 D11 与星级判定边界 | `visited` 判定逻辑 |

**工程侧必须保证的四条：**
1. `palette.ts` 导出**完整色表对象**而非散落常量，使"换色表"是一次对象替换。
2. 绘制代码**不得硬编码任何颜色或尺寸**，一律从常量表读取。
3. `pattern.ts` 的图案参数（方向 / 间距 / 线宽）为运行时可读，支持密度调节。
4. 可访问性选项**只影响渲染，不影响状态机** —— 不改变 `visible` / `visited` / `path` / 星级判定（GDD① §4.7 明确：玩家看得更清楚是 Accessibility 权利，不算作弊；本作无排行榜）。

## 6. 裁决记录（AX-1 / AX-2 已闭环）
