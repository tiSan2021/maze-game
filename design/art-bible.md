## 1. 视觉一句话定位

**暖调纸感几何 · 墨线高信号 · 一眼可读的"可读性优先"风格。**

把迷宫画成**一页方格纸上用铅笔与彩铅画出的谜题**：米白纸底上，墙体是打了斜线阴影的灰蓝块，六类功能元素用**彩铅信号色 + 独特几何形状 + 独特填充图案**标出。玩家视线在 1 秒内自然落在少数几处浓墨重彩上。

**三条不可动摇的原则（冲突时的裁决依据）：**

1. **可读性 > 美观**：任何装饰若削弱"1 秒读懂六类元素"，删除。
2. **形状优先、图案第二、颜色第三**：每个元素必须有**独立于颜色**的识别通道（色盲友好 + 小尺寸可辨）。v2 因亮底压缩亮度可用区间，图案编码升级为第二通道（论证见 §2②）。
3. **零外部美术资源**：所有视觉由 Canvas 2D 路径程序化绘制（论证见 §3，结论不变）。

## 2. 视觉身份九节

### ① 造型语言

全部元素由**基本图元 + 填充图案**构成。图元：矩形、圆角矩形、圆、三角形、正多边形、折线路径。无有机曲线、无位图纹理。

| 元素 | 造型 | 填充图案 | 关键识别特征 |
|---|---|---|---|
| 墙 | 满格直角矩形 + 右下假投影 | **45° 单向斜线**（间距 5px，2px 线宽） | 唯一带"厚度" |
| 通道 | 满格纸色底 + 方格网格线 | 无 | 唯一平涂无纹理 |
| 玩家 | 圆角矩形 24×24（圆角 6）+ 朝向三角 | **实心** | 唯一暖色（红）、唯一有朝向、唯一持续移动 |
| 钥匙 | 圆环 + 短杆 + 齿（18×18） | **实心 + 环形镂空** | 小尺寸 + 镂空 + 墨晕呼吸 |
| 门（锁定） | 满格矩形 + 锁孔 | **双向交叉网格**（间距 4px） | 最密纹理 = 最挡路 |
| 门（可开） | 满格矩形 | **实心**（与钥匙同色） | 由网格变实心 = 语义"可通过" |
| 出口 | 同心圆 ×3 + 向上箭头 | **同心圆纹理** | 唯一持续向外扩散动画 |
| 危险（可选） | 锯齿 / 尖角多边形 | 实心墨黑 + 红描边 | 唯一带尖角 |

**纹理密度 = 可通行性递进**（制图学传统，且完全契合纸感）：
`通道（无纹理，可通行） < 墙（单向斜线，不可通行） < 门锁定（交叉网格，最不可通行）`
门解锁后变为**实心**（醒目 = 通行）。这套密度的语义是自解释的，无需文字。

**圆角**：墙 0（结构感）· 玩家 6px · UI 面板 8px · 按钮 6px。所有元素居中对齐单元格，尺寸取偶数。

**多钥匙关的形状配对编码：**

| 配对 | 颜色 | 形状标记 |
|---|---|---|
| 配对 1（默认） | 深青 `#0E635A` | 菱形 |
| 配对 2 | 深紫 `#5A3189` | 三角形 |
| 配对 3 | 赭石 `#A85B1E` | 六边形 |

> 钥匙与对应门共享颜色 + 形状标记。v2 中**形状标记是配对的主要通道**（颜色在亮底上区分度不足，见 §2②）。

#### ⚠ 亮度阶梯在亮底上不成立 —— 量化核算与第二通道替换

这是 v2 相对 v1 的**唯一实质性退步**，必须记档：

| 项 | v1 暗底 | v2 亮底 |
|---|---|---|
| 满足"对底 ≥3:1"的元素亮度区间 | `[0.01, 1.00]` | **`[0.02, 0.26]`** |
| 对应 L* 可用跨度 | 78.4（7.5→85.9） | **42.6（15.5→58.1）** |
| 需容纳的信号数（六类 + 三档配对） | 8 | 8 |
| 平均 L* 间隔 | **10.1**（最小相邻差） | **6.09** |
| 小尺寸可靠区分的经验阈值 | ≥10 L* | ≥10 L* |
| **结论** | **达标** | **不达标** |

**最优分配下仍冲突**：即便精心分配，实测间隔只达 7.1–10.3；且三档配对色与主体色发生严重碰撞——配对 2 紫（L* 29.9）vs 出口（L* 30.3）**差 0.4**；配对 3 赭（L* 46.9）vs 玩家（L* 45.3）**差 1.6**。去色后这些成对元素无法区分。

**结论：亮度无法独立承担第二编码通道。v2 替换为「图案填充（hatching）」作为第二通道。**

**图案编码为什么是亮底上的更优解：**
1. **与颜色完全正交** —— 完全色盲亦可区分。
2. **亮底上表现优异，暗底上几乎不可见** —— 这是纸感风格相对 v1 冷调的**净增益**，v1 想用都用不了。
3. **契合锚点** —— 斜线阴影是铅笔的天然笔触，是"方格纸手绘谜题"的核心语汇。
4. **语义自解释** —— 纹理密度天然对应"可通行程度"（见 §2①）。

**图案编码的分层适用**：适用于**大面积元素**（墙 / 门 / 出口 / 通道状态：≥40px，5px 间距约 8 条线，清晰可辨）；**小面积元素**（钥匙 18px、玩家 24px）靠 **实心 vs 镂空 + 形状 + 尺寸 + 运动** 区分。

> **保留**：亮度阶梯在 v2 降级为**第三通道（辅助）**，仍按上表 L* 列单调排列（出口 30.3 < 钥匙 37.4 < 玩家 45.3 < 墙 55.6 < 纸 95.2），提供额外冗余，但**不得作为唯一区分依据**。

**对比度验收（维持 v1 标准）**：
- 信息图形**识别线** ≥3:1：墨线 10.18、墙斜线 6.72、门网格 6.79、玩家描边 7.73、记忆态轮廓 3.87 —— 全部达标。
- 大面积**填充**：墙 3.27、门锁定 2.97 —— 达标；记忆态墙 2.14 —— **记忆态不要求 3:1**（不承载需精确读取的信息，当前视野始终可见，且记忆态墙的识别由其轮廓 `#6B7A8F` 3.87:1 承担）。
- **通道状态区分（已知 vs 未知）的 3:1 由墙体承担**：已探索区可见墙（3.27:1），未知区无墙。通道底色差异（1.09:1）仅为辅助，刻意保持微弱以维持纸感。
- 文字 ≥4.5:1：主文字 12.80、次文字 5.05 —— 全部达标（AA/AAA）。

### ③ 线条与描边

（v1 规格不变，仅按亮底调整颜色语义）

| 项 | 规格 |
|---|---|
| 主轮廓线宽 | **2px**，色 `#1F3A5F` |
| 细节线宽（锁孔、钥匙齿、网格） | 1.5px |
| 强调线宽（出口环、可开门、焦点） | 3px |
| 纹理线宽（墙斜线 / 门网格） | 2px / 1.5px |
| 线端 / 连接 | `round` cap + `round` join |
| 虚线 | 禁止用于运动元素；仅允许用于"路径预览" |

**纸感的线条语义**：线条浓淡 = 墨色浓度 = 信息新鲜度。当前视野用**全浓度** `#1F3A5F`，记忆区用**淡墨** `#6B7A8F`，未知区**不画线**。这与铅笔稿的浓淡一致，是迷雾在纸感下的天然表达（见 §2⑦）。

**高 DPI 像素对齐**：canvas 实际像素 = CSS 尺寸 × `devicePixelRatio`，随后 `ctx.scale(dpr, dpr)`。描边路径落整数坐标 + 偶数线宽（2px），无需 0.5 偏移 hack。

### ④ 光影与层次

俯视角 2D 正交，**不做真实光照**。层次由以下绘制层构成（v2 因迷雾拆分为三层离屏，见 §3）：

| 层 | 内容 | 绘制频率 |
|---|---|---|
| L0 纸底层 | 纸面 `#F4F1EA` + 极淡网格 `#E4DCCE` | **烘焙一次，永不失效** |
| L1 记忆层 | 状态 B/C：记忆态墙 + 已探索通道 + 网格 + 铅笔笔迹 | **增量更新**（玩家跨格时，仅重绘脏格） |
| L2 动态层 | 状态 A：当前视野内的墙 + 通道 + 实体 + 玩家 + 特效 | 每帧（仅视野内，约 29 格） |
| L3 UI 层 | HUD + 菜单（**建议 DOM**） | 每帧 / 事件驱动 |

**假投影**：光源左上，投影右下偏移 (2,2)。纸感下投影用**暖灰 `#D5CBB8`（50% 透明）而非黑色**——纸上的阴影是铅笔灰，不是黑。仅墙、玩家、门拥有投影（有高度的实体）；钥匙、出口、网格线不投影（贴地）。

**发光处理（v2 变更）**：**暗底的径向渐变发光在亮底上无效，禁止使用**；同时**仍禁止 `ctx.shadowBlur`**（性能）。替代手段见 §2⑤「墨晕洇开」。

### ⑤ 动效基调（60fps）

**统一缓动**（不变）：入场/确认/拾取 `ease-out cubic`；循环呼吸 `ease-in-out sine`；失败 `ease-out back`；格移动 `smoothstep`。

**时长表**：格移动 120ms · 撞墙 80ms · 拾取 200ms · 开门 280ms · 过关 400ms · **失败 250ms**（v2.1 由 320ms 下调，见下）· 关卡切换 250+250ms · 按钮 hover/active 120/80ms。

#### v2 变更：亮底"发光"的三个替代手段

暗底的「径向渐变亮光叠加」是最强的注意力捕获手段，在亮底上完全失效。替换为**纸感三件套**：

**手段 A：墨色浓度呼吸**（替代 opacity 呼吸）
亮底上让元素"变淡"等于"消失"，语义错误。改为让**颜色在浓墨 ↔ 淡墨之间插值**，模拟铅笔反复描画。

**手段 B：线宽脉冲**（替代 scale 呼吸）
scale 呼吸在亮底上会破坏与网格的对齐感。改为**描边线宽脉冲**：`2px ↔ 3.5px`（±0.75px），保持几何位置不变，视觉上像"笔尖时轻时重"。

**手段 C：墨晕洇开**（替代径向渐变发光）
在元素外围叠加一圈**低透明度的同色晕**，模拟墨水/水彩在纸纤维上的洇开。实现：启动时在离屏 canvas 预渲染一张径向渐变精灵（元素色，中心 alpha 0.28 → 边缘 0），运行时 `drawImage` 缩放叠加。**这是亮底上唯一有效的"发光"等价物**，效率约为暗底发光的 40–50%（主观估计，需实测），因此需要**加大幅度补偿**。

| 常驻动画 | 周期 | v2 参数（替换 v1 的发光/scale） |
|---|---|---|
| 钥匙呼吸 | 1.6s | 墨晕半径 12↔16px（±2px），墨晕 alpha 0.28↔0.08；**线宽脉冲** 2↔3.5px；主体保持实心不透明 |
| 出口脉冲环 | 2.0s | **扩散墨环**：r 8→28px，线宽 3→1px，alpha 0.6→0，色 `#1B5220`（像在纸上画圈涟漪） |
| 门（可开）呼吸 | 1.2s | 门框描边在 `#083F39`（浓）↔ `#5FA899`（淡）插值；线宽 2↔3px；**锁孔形状由闭合圆变为开口缺口**（形状变化比颜色变化更有效） |
| 危险元素 | 0.8s | 左右抖动 ±1.5px（不变） |

**幅度补偿原则**：因墨晕效率低于发光，v2 所有常驻动效的幅度相对 v1 **上调约 50%**（墨晕 ±2px 半径、线宽 ±0.75px）。

**硬性规则（不变 + 增补）**：
- 全部 `deltaTime` 驱动；全局 `motionScale`（1.0 / 0.5 / 0）。
- 闪光频率 < 3Hz（WCAG 2.3.1）。**失败反馈为单脉冲（1 次 / 250ms），不构成周期性 flash** —— v2 原定「2 次 / 320ms」实测 6.25Hz，超标一倍，v2.1 已修正。
- 粒子上限 60；**关 9+ 有迷雾时降至 30**（补偿动态层开销）。
- 缓存 `Path2D` 与渐变对象，禁止在渲染循环内 `createRadialGradient`。

#### 视野：四态（关 1–8 全览 / 关 9+ 主线启用迷雾）

**四态定义与视觉手段**

| 态 | 名称 | 通道底 | 网格线（墨色浓度） | 墙体 | 实体 |
|---|---|---|---|---|---|
| **A** | **当前视野内**（visible） | `#F4F1EA` | `#A89878`（浓，2.51:1） | `#73879F` + `#3B5674` 斜线 + `#1F3A5F` 轮廓（3.27:1） | 全彩 + 常驻动效 |
| **B** | **已探索·已走过** | `#EDE7DA` | `#CFC5B0`（淡，1.52:1） | 记忆态 `#9AA8BC` + `#8092A8` 斜线 + `#6B7A8F` 轮廓（2.14:1） | 淡墨轮廓示意 |
| **C** ⚠ | **已探索·未走过**（**MVP 不可达**） | `#EDE7DA` | `#CFC5B0`（淡） | 同 B | 淡墨轮廓示意 |
| **D** | **未知**（unknown） | `#F4F1EA` | `#E4DCCE`（极淡，1.21:1） | **不绘制** | **不绘制** |

**B 与 C 的唯一区分：铅笔笔迹。** B 态通道叠加 45° 细斜线笔迹 `#9C8F73`（间距 8px，1px 线宽，40% 透明），模拟"走过的路被反复描过留下痕迹"。C 态无笔迹。

> ⚠ **C 态（已探索·未走过）在 MVP 不可达，禁止实现。** GDD① §4.7 四态模型下 `visited` 只记录**走过**的格（D11 单调），**看见但未走过**的格一旦离开视野半径即落入 `UNKNOWN` —— 该状态结构上不成立。要支持它需引入第三个 `seen` 集合 + 第五态。**裁决：MVP 不实现**（与 AX-1「增强记忆·看见即记住」同一议题，已列为 Comprehensive 候选增强）。上表 C 行参数保留仅供将来 AX-1 重启时参考，**Phase 4/6 不得据此实现**。

> **美术四态 ↔ 玩法渲染态映射（查表防误映射用）：** A（视野内，不论走过与否）↔ `VIEW_WALKED` / `VIEW_UNWALKED`；B（已探索·已走过）↔ `MEMORY_WALKED`；C（已探索·未走过）↔ **无对应渲染态（MVP 不可达），切勿据此实现**；D（未知）↔ `UNKNOWN`。工程侧 `cellRenderState` 须按 GDD① §4.7 单一函数推导，本表仅作查表防误映射之用。

**设计要点（三处关键判断）：**

1. **"已走过"在亮底上不能提亮，改为"加深 + 加笔迹"。** v1 的 +8% 提亮在亮底上无空间（纸已接近白）。纸感下"走过留下铅笔痕"是唯一自然的解，且**笔迹比提亮更有 tactile 质感**。

2. **"未知"用空白纸面，不用遮蔽层。** 斜纹 / 降饱和 / 灰色遮罩都会破坏纸感并产生额外绘制；而"还没画上去的空白纸"是纸感风格下最自然的未知表达——**未探索即未落笔**。实现上也最省：什么都不画。

3. **四态的主区分通道是"墨色浓度"而非亮度。** 网格线三档浓淡（2.51 / 1.52 / 1.21）+ 墨线两档（`#1F3A5F` / `#6B7A8F`）+ 有墙/无墙，构成完整的状态梯度。这与铅笔稿的浓淡语汇一致，是纸感相对冷调方案的**独特优势**。

**必采纳的体验优化：墙邻感知（wall-aware fog）**
若某墙格与任一已知格 8 邻域相邻，则以记忆态（B/C）绘制该墙格，即使其本身未被探索。
**理由**：纯迷雾下玩家看不到墙的走向，会不断"盲撞"，在 1-3 分钟短局里挫败感被放大。墙邻感知让玩家永远看得见墙的走向，只隐藏"墙后面有什么"，保留了探索感而消除了盲撞。成本为零（一次 8 邻域查询）。**强烈建议纳入。**

**视野半径**：**R = 2（2026-09-09 由 3 缩至 2），全程恒定，不随关卡变化**（切比雪夫距离，约 25 格）。两条理由（仍成立的上限约束）：① **性能**——R=5 达 8–9ms 明确超标，R=4 需同时启用降级预案 ①② 才勉强守住（见 §3 成本模型），故 R 上限锁死为 3、不得改大；② **玩法**——视野过大则迷雾失去意义。迷雾的"渐进引入"改由**关卡复杂度**维度实现（Q4）。**缩小 R（3→2）不在禁止范围**：玩家试玩反馈偏易，R=2 提升探索与记忆负担，且视野内格数更少、更省，未突破 <8ms 预算（性能实测待复测）。

## 3. 可绘制性说明

### 零外部美术资源：**结论不变，完全可行。**

v1 的五条论证在 v2 全部成立，且**图案填充（hatching）进一步强化了该结论**——斜线/交叉网格是纯路径绘制，若用位图反而更难做（需要无缝平铺纹理）。

### v2 新增：图案绘制方案

| 图案 | 绘制方式 | 性能策略 |
|---|---|---|
| 墙 45° 单向斜线 | 在格内 `clip()` 后画超出边界的平行线，或直接用 `moveTo/lineTo` 逐条绘制（间距 5px，约 8 条） | **预渲染为 40×40 tile 精灵**，运行时 `drawImage`。这是关键优化 |
| 门双向交叉网格 | 同上，两个方向各约 10 条 | 门的两种状态各预渲染一张 tile |
| 铅笔笔迹（B 态通道） | 45° 细斜线，间距 8px，40% 透明 | 预渲染 tile（含 2–3 个轻微随机变体，避免机械感） |
| 出口同心圆纹理 | 3 × `arc` stroke | 每帧（数量少） |
| 墨晕洇开 | 径向渐变 | **启动时预渲染精灵**，运行时 `drawImage` 缩放，**禁用 `shadowBlur`** |

**必做优化**：墙、门、笔迹三类图案**全部预渲染为 tile 精灵**。13×13 关卡约 60–70 个墙格，若每格重绘 8 条斜线则需约 560 次线段绘制；预渲染后降为 60–70 次 `drawImage`，**省约 85% 开销**。

### 渲染架构（v2 · 因迷雾重构）

v1 的双层（静态烘焙 + 动态）在迷雾下不再成立，改为**三层离屏 + 增量更新**：

| 层 | 内容 | 失效条件 | 重绘频率 |
|---|---|---|---|
| **L0 纸底层** | 纸面 + 极淡网格 | 永不 | **一次** |
| **L1 记忆层** | 状态 B/C：记忆态墙 + 已探索通道 + 网格 + 笔迹 | 探索集变化 | **增量**：玩家跨格时仅重绘 `dirtyCells` |
| **L2 动态层** | 状态 A：视野内墙 + 通道 + 实体 + 玩家 + 特效 | 每帧 | 每帧（仅视野内 ~29 格） |

**关键事实：视野不是每帧变化。** 玩家逐格移动，视野只在**跨格时**改变，最快约 8 次/秒（120ms/格），不是 60 次/秒。每次跨格仅影响视野边缘环（R=2 时约 12–24 格），**增量更新**即可，无需全量重烘焙。

**双路径设计**：
- **关 1–8（无迷雾）**：所有格子恒为状态 A → L1 记忆层为空 → **回退到 v1 全烘焙策略**（L0+L1+L2 全部烘焙，每帧一次 drawImage）。性能最优。
- **关 9+（有迷雾）**：走三层增量路径。

### 性能重估（1920×1280 实际像素 · 13×13 · 40px 格）

| 场景 | 每帧构成 | 估算 | 门槛 8ms |
|---|---|---|---|
| 关 1–8 全烘焙 | 1× drawImage(静态层) + 实体 + 玩家 + 特效（<30 次调用） | **<3ms** | ✓ 充裕 |
| 关 9+ 迷雾（R=3，**含 tile 预渲染**） | 2× drawImage(L0,L1) + 视野内 29 格 drawImage + 实体 + 玩家 + 特效 | **5–6ms** | ✓ 达标，余量较小 |
| 关 9+ 迷雾（R=3，**无 tile 预渲染**） | 同上但斜线逐条重绘（+560 次线段） | **9–11ms** | ✗ **超门槛** |
| **关 9+ 迷雾（R=4，50 格，含 tile）** | 2× drawImage + 视野内 50 格 + 实体 + 玩家 + 特效 | **6.5–7.0ms**（开阔区最坏 **7.5–7.6ms**） | ⚠ **勉强达标，余量 <0.5ms，无抗抖动能力** |
| 关 9+ 迷雾（R=5，81 格） | 视野内 81 格 | **8–9ms** | ✗ 超门槛 |

> **配置修订（2026-09-09）**：上表 R=3 行为旧配置（R=3）的实测/估算点。当前**实装值为 R=2**（玩家试玩反馈偏易，缩小 R 不在 ADR-03 禁止范围）；按成本模型代入 R=2（≈4×9×0.62≈22 格）可得更低的每帧耗时，**理论上比 R=3 更省，未突破 <8ms 预算**（性能实测待复测，未编造新数字）。R≤3 上限约束不变。

**每帧成本模型**（供按任意 R 换算，由 R=3/R=5 两点拟合）：
`耗时 ≈ 3.83ms（固定：2× drawImage + 实体 + 玩家 + 粒子 + 合成）+ 0.058ms × 视野格数`
视野格数 ≈ `(2R+1)² × 0.62`（通道密度估算），即 R=3→30、R=4→50、R=5→75 格；开阔区取密度 0.8，R=4 最坏 65 格。

**结论：重估后仍能守住 60fps / <8ms 门槛，但需以下前置条件（缺一则超标）：**
1. **必做**：墙 / 门 / 笔迹三类图案**预渲染为 tile 精灵**（否则 9–11ms，超标）。
2. **必做**：视野半径 **R ≤ 3**。R=4 仅在**同时启用降级预案 ①②** 时勉强守住（约 7.0ms，余量 1.0ms）；R=5 明确超标（8–9ms），**不可用**。
3. **必做**：L1 记忆层**增量更新**（全量重烘焙在跨格瞬间会产生掉帧尖峰）。

**降级方案（若实测超标，按序启用）**：
① 关 9+ 粒子上限由 60 降至 30（省约 0.5ms）→ ② 关 9+ 常驻动效降频（出口脉冲环 2.0s→3.0s）→ ③ 墨晕洇开仅应用于钥匙与出口，玩家不用 → ④ 极端情况：L2 动态层在半分辨率离屏绘制后放大（纸感柔和，视觉损失可接受）。

**迷雾新增工作量**：`visited`/`visible` 状态集 0.3 天 + 视野计算（Bresenham 视线或半径+墙遮挡）0.5 天 + 三层离屏与增量更新 0.5 天 + tile 预渲染 0.2 天 = **+1.5 天**。

**成本由 1.2 天升至 2.2 天，增量来源：**
- 亮度阶梯核算与重做色表：**+0.3 天**（纯计算 + 文档）
- 图案编码（hatching）实现：**+0.4 天**（三类 tile 预渲染 + 绘制逻辑；部分与墙体绘制重叠，实际增量偏小）
- **迷雾可访问性（v2 新增维度）：+0.3 天** —— 迷雾对低视力与认知障碍玩家不友好，Standard 档必须提供「迷雾减淡」与「关闭迷雾」两个选项（前者提高记忆态对比度至 3:1，后者全部按状态 A 绘制）

**维持 Standard 而非升/降档的理由：**
1. 2.2 天仍在 lean 可接受范围；Comprehensive 的 5–7 天对 1-3 分钟小游戏仍不划算。
2. 不可降到 Basic：图案编码是 v2 的**核心识别通道**（不是附加的可访问性工作），对比度达标是色表设计前提，两者都是必需项。
3. **亮底带来一进一退**：退步是色盲维度（亮度阶梯压缩，已由图案编码补偿）；**进步是光敏安全与长时间舒适度**——纸感无暗底高对比全屏闪烁，长时间观看显著更舒适。
4. 架构仍预留 Comprehensive 升级路径：`palette.ts` / `metrics.ts` / `motion.ts` / `pattern.ts` 集中常量，换色表或换图案密度不改绘制逻辑。

### 落实检查清单

- [ ] 每类元素**去色 + 去图案**后仍可通过形状区分
- [ ] 每类元素**去色**后仍可通过填充图案区分（实心 / 单向斜线 / 交叉网格 / 同心圆 / 无）
- [ ] 所有文本 ≥4.5:1，主文本 ≥7:1

## 5. 已知风险与缓解

### 风险 1：亮底压缩亮度通道，信号元素的"跳出感"显著下降

**描述**：暖调纸感下，满足"对底 ≥3:1"的元素亮度被压到 `L ≤ 0.26`（L* 区间仅 42.6），导致：
- **对比度天花板下降**：玩家对比度由 v1 的 12.1:1 降至 **4.71:1（-61%）**，钥匙由 9.10:1 降至 6.31:1。虽均超 3:1 验收线，但"第一眼捕获"能力明显减弱。
- **发光手段失效**：暗底的径向渐变发光（最强注意力捕获手段）在亮底无效；替代的"墨晕洇开"效率约仅为其 40–50%（主观估计，需实测）。
- **亮度阶梯不可用**：8 个信号的平均 L* 间隔仅 6.09，远低于小尺寸可靠区分所需的 ≥10；即便最优分配，配对 2 紫 vs 出口仍只差 0.4 L*。

**缓解（已在 v2 落地）**：
- 图案填充（hatching）承担第二编码通道 —— **这是亮底的净增益**，暗底上图案几乎不可见，用不了。
- 常驻动效幅度上调 50% 补偿墨晕效率损失。
- 状态联动改用**填充图案突变**（网格→实心），比颜色变化更醒目。
- 玩家保有多重冗余识别通道：唯一暖色（红）+ 唯一有朝向 + 唯一持续移动 + 唯一带投影 + 尺寸最大。

**残余风险（可接受）**：跳出感净损失估约 5%（损失 15–20%，补偿回 10–15%）。**此估算为纸上推算，未经实测，由下列验收门禁判定。**

> ### 验收门禁 G1 · 六类元素 1 秒可识别性
>
> | 项 | 内容 |
> |---|---|
> | **执行时点** | **Phase 6 打磨阶段**（关 1 原型可玩之后、发布之前） |
> | **执行人** | **`quality-lead`** |
> | **方法** | 找 **3–5 名未参与开发**的测试者，将关 1 画面**闪现 1 秒**后隐藏，令其指认六类元素（墙 / 路 / 玩家 / 钥匙 / 门 / 出口） |
> | **通过标准** | 六类元素**平均识别率 ≥ 90%**，**且任一单类不低于 80%**（设单类下限，防止"平均达标但某一类塌陷"） |
> | **不通过处理** | 按序上调信号色深度后重测：钥匙 `#0E635A`→`#0A4E47` → 出口 `#1B5220`→`#123A16`（同心圆纹理同步加深至 `#0C2A0F`）→ 玩家 `#C4382E`→`#A82C24`。若仍不达标，加大常驻动效幅度（墨晕 ±2px→±3px）后重测 |
> | **为什么必须是门禁** | 这是"1 秒读懂六类元素"这一核心目标的**唯一可判定验证点**。对比度与 L* 间隔只是代理指标，无法替代真人识别——尤其本方案已知存在"跳出感下降 61%"与"墨晕效率仅 40–50%"两处未实测的不确定项。写成"建议"必然被跳过，故升级为门禁 |
>
> **注**：加深信号色在亮底上**只会提高对比度、不会降低**（元素越深 CR 越高），因此上述调整是安全的，不存在顾此失彼。

### 风险 2：迷雾使静态层不再静态，可能击穿帧预算

**描述**：v1 的"静态层烘焙"依赖完全静态，迷雾引入后每帧绘制量随视野半径增长。

**缓解**：三层离屏 + 增量更新 + 三类图案 tile 预渲染 + 视野半径 R≤3 + 双渲染路径（关 1–8 回退全烘焙）。详见 §3 性能表。

**硬约束（必须传达给程基岩）**：**tile 预渲染、R≤3、L1 增量更新三者缺一，关 9+ 即为 9–11ms，超标。** 若实测仍超标，按 §3 四级降级方案启用。验收门槛不变：1920×1280 实际像素稳 60fps，绘制耗时 <8ms。

### 风险 3：亮底对未来扩展的容量限制

**描述**：亮底下所有信号元素必须挤在 `L ≤ 0.26` 的窄带内（L* 15.5–58.1，跨度 42.6）。当前 8 个信号已将该区间用满（平均间隔 6.09，低于阈值），**任何新增信号元素（新道具、新机制、第 4 种配对钥匙）都会进一步加剧区分困难**。

**缓解**：
- 扩展时优先新增**图案**而非新增颜色（图案维度当前仅用了 5 种：无 / 单向 / 交叉 / 同心圆 / 实心，仍有空间：点阵、水平线、波浪线、网格点）。
- 新元素优先复用已有颜色的**形状变体**。
- **硬上限预警**：配对钥匙**不超过 3 种**。若关卡设计需要第 4 种，必须引入新图案而非新颜色。

### 风险 4（v1 风险 3 的收敛版）：视觉锚点冲突

v1 时本项为"待暴露"风险，v2 已完成对齐（用户裁决 D1/D2，本文档为对齐结果），风险解除。**残留**：若后续概念文档仍有与本文档冲突的视觉细节，按 §1 三条原则裁决；配色/度量/动效/图案四类常量集中于 `palette.ts` / `metrics.ts` / `motion.ts` / `pattern.ts`，换风格 = 改常量，绘制逻辑不动。

**Q2 与 §4 迷雾可访问性选项的关系（不重复，三者并存）**：
墙邻感知、迷雾减淡、关闭迷雾作用于**三个不同层面**，不构成功能重叠——
> **墙邻感知让所有人看得见"墙往哪走"（空间导向，面向全体玩家）；迷雾减淡让低视力者看得清"我去过哪"（视觉对比，2.14:1→3:1）；关闭迷雾让记不住的人不必记（机制移除，面向认知障碍玩家）。**

且后两者实现成本极低、不可再省：**迷雾减淡** = 换一组记忆态色常量（+0.1 天，且是 §4 对比度承诺的组成部分）；**关闭迷雾** = 复用关 1–8 已有的无迷雾全烘焙路径，**无需新增渲染代码路径**。按 lean 原则这属于"成本近零、收益明确"，**不建议简化**。
