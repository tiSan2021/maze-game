> Phase 2 · 系统设计 | 作者：文策渊（设计策略师）| 状态：待主理人评审
> 上游：`concept.md` v2.1（§3 动词、§5.1、§7、§8）｜ `art-bible.md` v2（§HUD、§视野）

## 1. 目的与范围

**本 GDD 定义**：键盘输入处理、网格移动、**走廊滑行**、撤销/重开、视野可见性集合的**计算**（非绘制）、顶部状态条 HUD、关卡内 UX 流程。

**不定义**（属其他文档）：地图绘制与动画（美术圣经）｜关卡数据模型与段切分（GDD②）｜开门规则（GDD③）｜星级算法（GDD④）。

**一句话**：把"走"的成本压到最低，把输入语义定义到工程侧无需回问的粒度。

## 2. 核心机制

### 2.1 五动词在本系统的落位

| 动词 | 本系统承载 | 备注 |
|---|---|---|
| **走** Move | 4 向网格移动 + **走廊滑行** + 长按连走 | 物理动词，本作唯一 |
| **看** Scout | 视野集合计算（§4.6）+ 已访问集合 | 关 1–8 辅助 / 关 9 起核心（D2）；可见/N 态由本系统算，绘制在美术侧 |
| **配** Match | 不在此处判定，仅负责"走到了某格"这一触发 | 开门/拾钥匙规则见 GDD③ |
| **省** Optimize | 产出 `path` 与 `steps` 供 GDD④ 判定 | 本系统只记录，不评分 |
| **撤** Undo | Z 单步撤销、R 整关重开 | 撤销语义见 §4.5 |

### 2.2 移动四条基本规则

1. **格子对齐**：角色恒处于某个格中心，移动是"格 → 相邻格"的离散跳变。视觉插值 120ms/格（美术侧），**逻辑上移动瞬时完成**。
2. **撞墙不消耗**：向不可通行方向移动 → 请求被完全拒绝，**不产生 step、不计步数、不写入 `path`**，仅播放受阻反馈。
3. **一次按下 = 一次滑行**（走廊滑行，§4.2）。
4. **长按连走**：上一次滑行结束后自动发起下一次滑行。

### 2.3 走廊滑行（**MVP 硬约束，不可砍**）

按一次方向键，角色沿该方向连续前进，直到遇到需要决策的位置。

**为什么是硬约束**：本作物理动词只有"走"一个（§2.1），取消此机制 = 直接引入 R2「寻路无聊」——玩家在长廊里反复按键做体力劳动。它是支柱二「想的时间 > 走的时间」唯一的执行手段，不是体验优化项。

### 2.4 撤销与重开（零惩罚）

- **Z**：撤销**一整次滑行**（见 §4.5 粒度说明）。
- **R**：整关重置到初始状态。
- 二者均**不计入失败统计**、不影响关卡解锁。

### 2.5 视野与状态（D2 / Q2）

- 关 1–8：`visionMode = 'full'` → **三态**（走过的 / 未走的 / 墙）。
- 关 9 起：`visionMode = 'fog'` → **四态**（视野内·走过的 / 视野内·未走的 / 视野外·走过的记忆区 / 未知）。
- **墙邻感知启用**（Q2）：玩家永远看得见与已知区域相邻的墙的走向，消除盲撞。

## 3. 数据结构 / 状态

```ts
type Dir = 'up' | 'down' | 'left' | 'right';

/** 输入层状态 */
interface InputState {
  /** 按下的方向键栈，栈顶 = 当前生效方向 */
  dirStack: Dir[];
  /** 长按连走是否已激活 */
  repeatActive: boolean;
  lastRepeatAtMs: number;
}

/** 视野层状态（每帧由 §4.6 重算，可缓存） */
interface VisibilityState {
  /** 当前视野内的格（含 R=3 半径内的地板 + 墙邻感知的墙） */
  visible: Set<CellKey>;
  /** 曾经走进过的地板格。**单调递增，撤销不回滚**（见 §4.5） */
  visited: Set<CellKey>;
}

/** HUD 视图模型（数据来源 RunState，不含判定逻辑） */
interface HudState {
  levelLabel: string;          // "第 7 关" / "每日 · 高"
  keys: { color: KeyColor; held: boolean }[];   // ≤3
  doorsOpened: number;
  doorsTotal: number;
  steps: number;
  elapsedMs: number;
  undoAvailable: boolean;
  showFogLegend: boolean;      // 关 9+ 或每日种子
}
```

`RunState` / `Step` / `CellKey` 的完整定义见 **GDD② §3**——本系统**只读消费，不重新定义**。

## 4. 算法 / 规则

### 4.1 单个移动判定

```
canMove(state, cell, dir):
  next = neighbor(cell, dir)
  if next 越界 or next.grid == 'wall':        return BLOCKED
  if next 是未开启的门:
       if 持有该门同色钥匙: return OPEN_AND_ENTER   // 见 GDD③
       else:                return BLOCKED
  return OK
```

**规则**：`BLOCKED` 不产生任何副作用；`OPEN_AND_ENTER` 产生 step + 一个 `door` 进度事件（GDD③）。

### 4.2 走廊滑行终止谓词

一次滑行 = 反复单格前进，直到满足任一停止条件。**每次进入新格 C 后按序求值：**

| 序 | 条件 | 语义 |
|---|---|---|
| **S1** | 前方（方向下一格）不可通行 | 抵墙 / 抵无法开启的门，停在当前格 |
| **S2** | C 上有**实体**（钥匙 / 门 / 出口） | 有意义的格子，必须让玩家 consciously 停下 |
| **S3** | C 是**通行路口**：存在至少一个**当前可通行**的垂直方向邻格 | 出现真实选择，交还决策权 |
| **S4** | C 在**本次滑行**中已走过 | **环形走廊保护**，防止无限循环 |

> **S4 不可省略**。环形走廊中每一格的垂直邻格都是墙 → S3 永不成立 → 无 S4 将无限绕圈。这是本机制最容易漏掉的边界。
>
> **S3 的"可通行"定义**：该垂直邻格为地板、已开启的门、或持有钥匙的锁门。**当前打不开的门不构成路口**（不构成当前决策）。

### 4.3 长按连走

- **禁用系统级按键重复（OS auto-repeat）**，自行管理节奏，避免跑飞。
- 时序：`initialDelay = 220ms`，之后每 `110ms` 发起一次新滑行，**且必须等上一次滑行结束**。
- 松开按键立即停止。

### 4.4 多键与失焦

- 同时按下多个方向：以 `dirStack` **栈顶**（最近按下）为准。
- `window.blur` → 清空 `dirStack` 与 `repeatActive`（防按键卡死）。
- 方向键/WASD 需 `preventDefault`，避免页面滚动。

### 4.5 撤销语义（**D5**，工程侧易误解，重点）

**实现方案：快照栈。** 每次成功滑行前压入一份状态快照。

```
snapshot = { pos, keysHeld, doorsOpened, pathLength, steps }
```

**撤销行为表**：

| 状态 | 撤销时是否回滚 | 理由 |
|---|---|---|
| `pos` / `keysHeld` / `doorsOpened` | ✅ 回滚 | 保持世界状态一致 |
| `path` / `steps` | ✅ 回滚 | **D5：回头路记录随之擦除** |
| **`visited`** | ❌ **不回滚（单调递增）** | 见下 |
| `elapsedMs` | ❌ 不回滚 | 计时是真实时间，不返还 |

> **本 GDD 新增决策（需主理人知悉）**：`visited` **不随撤销回滚**。
> 理由：`visited` 是玩家的**认知地图**，是 R1「迷路挫败感」的核心缓解手段。若撤销会擦掉走过的痕迹，玩家撤销后会"忘记自己去过哪"，在关 9+ 迷雾下尤其致命——等于惩罚了探索。
> 这同时意味着：玩家探索一条死路、撤销、仍保留"那里是死路"的知识，且不影响三星。这与 D5 已接受的取舍（撤销可"磨"出三星）一致：**学到的是知识，走过的才计费。**

**撤销粒度 = 一次滑行**（不是单格、也不是到分叉点的整段回头）。理由：一次按键对应一次滑行，撤销与按键 1:1 最符合直觉；单格撤销在长滑行后会让玩家连按十几次。

> ⚠️ **这不是 bug，是既定语义**：工程侧**不得**实现"撤销仍保留回头路记录"。见 `concept.md` §5.4 注。

### 4.6 视野计算（Q2 · 本系统是唯一定义处）

**参数**：`R = 3`，**切比雪夫距离**（`max(|dx|,|dy|) ≤ 3`），全程恒定不随关卡变化（美术侧性能测算：R=5 达 8–9ms 超标）。

**设计决策：纯半径，不做视线遮挡（无 Bresenham）。**
理由：13×13 是小网格，遮挡会让可见区支离破碎、难以推理，直接伤害支柱一「可推理的公平」并抬高 R1 风险；而遮挡真正有用的部分（知道墙的走向）已由**墙邻感知**完整提供。此决策可翻转，但需重过美术侧性能门禁。

**墙邻感知规则**（Q2）：
> 一个**墙格**若在**任意已访问地板格**或**任意当前可见格**的 8 邻域内，则该墙格加入 `visible`。

```
computeVisibility(level, pos, visited):
  visible = new Set()
  radiusSet = { c | chebyshev(c, pos) <= 3 }
  for c in radiusSet: visible.add(c)                     // ① 半径内的地板与墙

  for c in (visited ∪ (radiusSet ∩ 地板)):               // ② 墙邻感知
      for w in 8邻域(c): if level.grid[w] == 'wall': visible.add(w)

  return visible
```

副作用：探险过的区域，其周围墙**永久可见**（随 `visited` 单调增长），玩家永不丢失空间框架。

### 4.7 三态 / 四态推导（**单一函数，禁止分支版本**）

```
cellRenderState(level, c, pos, visited, visible):
  grid = level.grid[c]
  if grid == 'wall':
      if level.visionMode == 'full': return 'WALL'
      return visible.has(c) ? 'WALL' : 'UNKNOWN'

  // 地板
  inView = (level.visionMode == 'full') || visible.has(c)
  walked = visited.has(c)

  if inView:  return walked ? 'VIEW_WALKED' : 'VIEW_UNWALKED'
  // 不在视野内 ⇒ 只可能是 fog 模式
  return walked ? 'MEMORY_WALKED' : 'UNKNOWN'
```

**推导出的状态数自动符合 D2**：

| `visionMode` | 实际出现的集合 | 对应 |
|---|---|---|
| `'full'`（关 1–8） | `VIEW_WALKED` / `VIEW_UNWALKED` / `WALL` | **三态** |
| `'fog'`（关 9+） | 上述三者 + `MEMORY_WALKED` / `UNKNOWN` | **四态** |

> 关 1–8 **永远不会产出 `UNKNOWN` 与 `MEMORY_WALKED`**。美术侧无需为关 1–8 实现未知区表现。
> **可访问性覆盖**：美术圣经提供「迷雾减淡 / 关闭迷雾」两个选项。二者**仅替换上述函数的返回值做渲染**，**不改变 `visible`/`visited` 集合、不影响 `path` 与星级判定**。玩家看得更清楚是 Accessibility 权利，不算作弊（本作无排行榜）。

### 4.8 HUD（Q3：顶部状态条）

美术侧规格：顶部 **32px** 横条，DOM 实现（`aria-live` 可读），**不占用迷宫区高度**（守住 A6 一屏一关）。

| 区 | 内容 | 备注 |
|---|---|---|
| 左 | `levelLabel`（"第 7 关" / "每日 · 高"） | |
| 中左 | 钥匙槽 ≤3：**颜色 + 符号双重编码**，未持有显示空槽 | 与 GDD③ 一致，≤3 种 |
| 中 | 门进度 `doorsOpened/doorsTotal` | 无锁关卡该区留空 |
| 中右 | 步数 / 计时 | |
| 右 | 操作提示 `Z 撤销 · R 重开 · Esc 返回` | |
| 关 9+ / 每日追加 | **四态迷你图例**（走过 / 见过 / 未知 三色块 + 文字） | 美术 v2 增补，降低认知负担 |

**UX 流程**：

```
标题 → 关卡选择 ──选关──> 关卡内 ──抵达出口──> 结算（星级 + 明细）
                              │ Esc                    │
                              └────> 关卡选择（放弃本关，不写进度）   │
                                                        ├ 下一关（1星即解锁）
                                                        ├ 重玩本关
                                                        └ 返回关卡选择
```

结算**必须显示星级明细**（见 GDD④ §2.3），否则玩家不知道为什么丢星。

## 5. 与其他系统的接口

| 对端 | 方向 | 内容 |
|---|---|---|
| **GDD②** | ← | `RunState` / `Step` / `Level` / `visited` 的唯一定义 |
| **GDD③** | → | 询问 `canMove` 的门判定；接收"拾取/开门"是否构成**进度事件** |
| **GDD④** | → | 交付 `path`（含每步 `progressEvent`）、`steps`、`elapsedMs` |
| **GDD⑥** | ← | 每日种子关卡以 `Level` 形式注入，`visionMode` 恒为 `'fog'` |
| **渲染层** | → | 每帧交付 `VisibilityState`；由 `cellRenderState` 决定绘制态 |
| **存档层** | → | 关卡选择进度、最佳星级；`(关卡 fighting state 不持久化，重开即丢)` |

## 6. 边界与异常

| # | 场景 | 处理 |
|---|---|---|
| E1 | 环形走廊滑行 | S4 兜底终止，最多前进 `gridSize²` 格 |
| E2 | 长按到死路 | 滑行停下后连走继续发起，被 S1 立即拒绝；需有节流避免刷帧 |
| E3 | 滑行途中按下新方向 | 缓冲**最多 1 个**输入，当前滑行结束后执行；多余的丢弃 |
| E4 | `path` 为空时按 Z | 无操作，不报错 |
| E5 | 同时按下相反两方向 | 取栈顶，行为确定，无抖振 |
| E6 | 窗口失焦 | 清空输入栈 + 停止连走；计时继续（见 §6-E7） |
| E7 | 结算前按 R | 本局作废，`path` 清空，计时重置 |
| E8 | 门在前方但无钥匙 | S1 停止于门前，**不计步**、不产生进度事件 |
| E9 | 地图外坐标 | `canMove` 返回 BLOCKED，永不越界 |

## 7. 可判定验收口径

| # | 判据 | 方法 |
|---|---|---|
| **V1** | **按键次数 < 移动格数 × 40%**（R2 验收） | 主线 12 关各录一次首次通关；任一一关超标则该关重设计 |
| **V2** | 撞墙不产生 step | 单测：向墙走 10 次，`steps === 0` 且 `path.length === 0` |
| **V3** | 环形走廊不死循环 | 构造环形关卡，单次滑行必须终止且 ≤ `gridSize²` 格 |
| **V4** | 走廊滑行在有实体/路口处停止 | 单测：对 GDD② 示例关卡断言滑行终点集合 |
| **V5** | 撤销后 `path`/`steps` 回滚、`visited` **不**回滚 | 单测：走 5 步后撤销，`path.length === 4` 且 `visited.size` 不变 |
| **V6** | 三态/四态与 `visionMode` 严格对应 | 关 1–8 任意帧**不出现** `UNKNOWN` / `MEMORY_WALKED`；关 9+ 可达两个状态 |
| **V7** | 墙邻感知生效 | 站在记忆区旁，相邻墙必在 `visible` 中 |
| **V8** | HUD 不迫使滚动 | 1080p 下 13×13（520×520）+ 32px HUD ≤ 592px 可用高度 |

## 8. 风险与缓解

| # | 风险 | 缓解 | 验收 |
|---|---|---|---|
| **M1** | 走廊滑行"走过头"，玩家错过分叉 | S2/S3 在任何有实体或真实选择的格子停止；只跳过**纯通道** | V4 |
| **M2** | 长按连走跑飞 | 禁用 OS auto-repeat + 220/110ms 节流 + 等滑行结束 | 单测：按住 3s 后角色位置可预测 |
| **M3** | 撤销语义被实现成"仍保留回头路记录" | §4.5 用表格+警告显式写出；`visited` 单调单独列条 | V5 |
| **M4** | 关 1–8 误实现四态，美术做无用功 | `cellRenderState` 单一函数自动产出三态 | V6 |
| **M5** | 视野遮挡算法被自行加回来 | §4.6 显式声明"纯半径"及理由；若改需重过性能门禁 | V7 + 美术性能门禁 |
| **M6** | 认知过载（HUD 信息过多） | HUD 常量（≤3 钥匙槽 + 门进度 + 步时 + 提示）；关 9+ 才追加图例 | V8；Phase 6 由 `quality-lead` 做识别率门禁 |
