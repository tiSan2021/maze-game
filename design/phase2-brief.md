## 2. 每份 GDD 的八节结构（策略师规范）

每份 GDD 须含以下八节，缺一不可：

1. 目的与范围
2. 核心机制
3. 数据结构 / 状态
4. 算法 / 规则
5. 与其他系统的接口
6. 边界与异常
7. 可判定验收口径（lean：每条风险/特性都要有可判定的验收口径）
8. 风险与缓解

## 3. 锁定输入（必须体现在对应 GDD 中，不得推翻）

以下 12 项决策与接口约束已冻结，逐一映射到 GDD：

| 决策 / 约束 | 内容 | 落位 GDD |
|---|---|---|
| 走廊滑行 | 按一次方向键自动走到下一个分叉点，**MVP 硬约束**（非锦上添花） | ① |
| 撤销擦除 | 撤销回滚 path，**回头路记录随之擦除**（D5） | ① |
| 顶部状态条 HUD | 钥匙/门/步数/撤销 走顶部横条（Q3，零工时） | ① |
| 「看」动词 | 关 1–8 三态（走过/未走/墙）、关 9 起四态（视野内·走过 / 视野内·未走 / 视野外·记忆区 / 未知）；**墙邻感知启用**（Q2，8 邻域查询） | ① + ② |
| 关卡尺寸递进 | L1–3 = 9×9（内 7×7）/ L4–8 = 11×11（内 9×9）/ L9–12 = 13×13（内 11×11），**含外墙** | ② |
| 一屏一关 | 13×13×40 = 520×520 ≤ 592px，无摄像机滚动（C3） | ② |
| 共用数据结构 | 数据模型须同时满足**手工关卡 + 程序化生成器**（D4 升级为 MVP 硬需求，4b） | ② |
| 进度事件模型 | 钥匙拾取 / 门开启 作为进度事件，支撑段切分 | ② |
| 段切分算法 | 段 = 相邻两进度事件间的路径；**段内重复格 = 回头路**；跨段重复 = OK。1星=通关 / 2星=≤1 回头路段 / 3星=0 回头路段 | ② + ④ |
| 锁钥规则 | 同色配对、门面显色、依赖链 ≤2 层、钥匙 ≤3 种、死路分支**禁止互连**（D9，4d） | ③ |
| 星级阈值 | 通关 + 零回头路（D3），**不算每关最优解** | ④ |
| 求解器 G3 | 验证设计标注的 `expectedSolution` 本身为零回头路解（O(path) 遍历），**不可实现为搜索最优解**（状态空间 2^169） | ⑤ |
| 六门禁 + 构造式 | G1–G6 全阻断 + 构造式生成 4 步（先造零回头路主干解 → 撒钥匙门 → 加死路 → 复验）；G6 = 每日种子两天分别命中中/高档（D8） | ⑤ + ⑥ |
| 确定性 PRNG | **mulberry32 + 种子绑定版本号**（D10，4c） | ⑥ |
| 每日种子 | 两张（中/高各一，玩家自选，主线通关后解锁）（D8） | ⑥ |
